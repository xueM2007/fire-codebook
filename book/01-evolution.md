# 第 1 章　从两张纸到三行火

**这一章你会得到什么**：能指出每次改版拿走的具体成本，还能分清哪些麻烦是新表示带来的。定位中的 L 是源文件的物理行，空行也占一个号码。 代码框保留关键原行，行号不连续时，中间行见标注的源文件区间。

## 1.1　v1　让每个判断都能用手指着读

读这个版本会用到三种基础写法。int（integer，整数类型）存格子状态；if（conditional statement，条件判断）表示条件成立才执行；for（for loop，计数循环）控制行列。std::cin（standard input stream，标准输入流）的 >> 从字符里解析一个整数；std::cout（standard output stream，标准输出流）的 << 向外写。这里的双尖号不是位移。方括号 [i] 以从零起的下标访问容器，访问者自己负责范围。

**这一版想干什么**：先把第 0 章那两张纸写成程序。二维数组（two-dimensional array，用行列两个下标取格子）读起来像方格纸。这里实际用嵌套向量（nested vector，外层容器保存一排内层容器）：sta[r][c] 要先找到第 r 行，再找到那一行的第 c 格。地图四周多一圈初值为零的格子，靠边的树也能照常检查四个方向。

**卡在哪**：题目规模上有约 2.68 亿格。按常见四字节整数（int，通常用来存放普通整数）估算，一张实心地图已经约 1 GiB；额外两圈和每行容器还没计入。一轮要把旧图完整复制给临时图，算完又把临时图赋回去。即便这一步一棵树都没烧，这两处依然要触碰整片内存。

**这一版改了什么**：第 26、31 行用 freopen 把标准输入输出重新接到文件；它接收路径、模式、原来的流，失败返回空指针。第 41 行多配两行两列，第 81–95 行把外部坐标各加 1。第 106–120 行只从 sta 读、向 temp 写；把第 114 行改成写 sta，就可能让一行连续的树一拍全烧起来。

## 1.2　v2　把复制改成交换，把字符攒成块

先分清地址和内容。指针（pointer，保存地址的值）写成 char* p；*p 取该地址的一个字符，++p 改的是地址。只读限定 const（const qualifier，通过这个名字不可改所指值）不妨碍 p 移动。fopen、fread、fclose 分别负责开流、读若干项、关流；一次读取返回的‘项数’只有在每项一字节时才等于字节数。while（while loop，条件成立就反复执行）适合数量未知的连续空白。

**这一版想干什么**：算法还按格子逐个判断。换的是数据进出机器的方法。缓冲区（buffer，临时存放一批数据的一段空间）把读文件和辨认数字拆成了两步，程序可以顺着内存往前走，不必给每个格子做一次通用格式转换。

**卡在哪**：上一版每步才创建临时图；把它提到循环外后，新图里可能留下上一次使用时的旧值。比如这里本轮应保留空地，作者不能只是跳过空地不写。第 131–132 行就是这个保证。另一处隐患是第 32 行发出整文件读取请求，却没检查究竟读进多少字节。

**这一版改了什么**：第 26–44 行一次读取并扫描字符。第 92 行在步循环外分配 temp；第 121–136 行给所有真格赋值再 swap：交换（swap，互换两个容器管理的存储）不需要逐格复制。输出第 148–165 行分配 2²² 字节，每个格子产生一枚数字字符和一个分隔符。读计时从打开文件前开始，含文件读取，不能和上一版的起点混算。

## 1.3　v3　让一个格子占一个字节

uint8_t（unsigned eight-bit integer，八位无符号整数）表示 0–255；std::size_t（size type，对象大小类型）适合装内存中的元素数或下标。`static_cast<T>`(x)（explicit type conversion，显式类型转换）要求将 x 转换成 T，并不能代替对 x 是否在允许范围内的检查。

**这一版想干什么**：字节（byte，通常由八个位组成）装得下 0 到 3。把很多独立的行改成一条长带子，行跨度（stride，从本行同一列走到下一行同一列要跨多少元素）直接参加下标计算。这样相邻行也位于同一片连续分配的空间里。

**卡在哪**：把第 r 行误算为 r×n 会跳错地方：作者沿用了上下左右各一格的空边框，真正行宽是 n+2。以 n=6 为例，第二行第二个内部格子用内部坐标 (2,2) 算得 18；把步长写成 6 就变成 14，仍可能落在合法内存中，所以只看程序有没有崩是不够的。

**这一版改了什么**：第 35–41 行检查实际读入字节；第 60–63 行让 stride 成为适合表示内存大小的无符号类型，并用两个连续的 uint8_t 容器存两代。第 134–149 行的上下邻分别在 idx−stride 和 idx+stride，左右只差 1。static_cast 是显式类型转换，让编译器检查这类转换是否合法；它并不会自动检查所有乘法是否超界。

## 1.4　v4　并排放同一件事的答案

三个运算先在一位上试：按位与（bitwise AND，逐位取交集）在两边皆为 1 时得 1；按位或（bitwise OR，逐位取并集）在任一边为 1 时得 1；按位取反（bitwise complement，把每位 0 和 1 对调）写作 ~。左移、右移（bit shifts，把无符号数中的位向高位或低位搬）这里才用 <<、>>。uint64_t（unsigned 64-bit integer，六十四位无符号整数）把这套演算放大到一排 64 格。

**这一版想干什么**：位运算（bitwise operation，对一个字中每一个二进制位置独立做逻辑运算）在这里有一个直观用途：一行 64 格的问题“哪些格是火”只要一对字就能回答。作者不给每格写两位相邻的编码，而是把同一种属性的 64 个位放在同一字中。

**卡在哪**：旧图和新图各两张位面，另有第五张火图。它免去四邻取火时反复解码旧状态，却引入整图的写入和再读取。位宽 64 也带来两个新接缝：每行未必刚好用完一个字，左右邻火还能跨字。同一行第 63 列烧到第 64 列合法，某行末列直接烧到下一行首列则不合法。

**这一版改了什么**：第 62–68 行分配四张状态面和一张 fire。第 146–155 行用掩码（mask，只挑选指定位的二进制模式）限制回春范围，第 168 行取出全图旧火。第 179–185 行把同一字左右移并借相邻字的一位，再用树与邻火的交集筛出新火。没有哪条指令在做一次完整的森林更新；是一小组逻辑式共同完成。

## 1.5　v5　两次派工，先提取火，再更新树

并行指令（compiler directive，写给编译器的特殊指示）#pragma omp parallel for 把后面的循环交给线程团队分摊；schedule(static) 指静态调度（static scheduling，预先分配迭代范围）。这两个词决定谁算，不重新定义算什么。

**这一版想干什么**：共享内存允许几条线程读同一张旧图。写入却必须先划界：同一地址不能让两个线程各自随意改。这里按字生成火图，再按行更新新图，两段各自的输出下标天然不同，适合分工。

**卡在哪**：第一个循环的一段火图可能会被第二个循环的另一个线程读取。你不能仅凭‘我负责的行写好了’就开始第二段：边界那一行还需要别人写的火。每步需要两次进入并行区（parallel region，由一个线程团队共同执行的代码区域），循环之间也必须有先后。

**这一版改了什么**：第 159、166 行的 parallel for 是‘建立团队并分配循环’的组合指令。schedule(static) 是静态调度（static scheduling，预先分配迭代范围）；不用每处理一个字就去向全局队列取下一个字。第 184–185 行在两段计算之后交换两张位面。

## 1.6　v6　让团队包住时间，而不是让时间包住团队

single（single construct，单线程执行构造）让团队任选一个成员执行结构块；它在这里末端自带会合。团队是一起到达同步点的所有参与者，和‘某时刻恰好在计算的人’不一定一样。

**这一版想干什么**：同一队人完成所有时间步，但没有取消工作之间的依赖。栅栏（barrier，一队线程全部到齐才能进入下个阶段的同步点）让快线程不能先交换旧图。分清‘一人做’和‘别人等到它做完’是读这一版的钥匙。

**卡在哪**：事件阶段不能让每人把同一条事件再消费一次；只让一人处理，但没做事的人必须看到事件改过的地图。火平面的生产和消费同样隔着一次同步。全图 fire 仍需约 32 MiB，大图每步至少要写完它，下一阶段又从它读。

**这一版改了什么**：第 116–122 行把团队移到步循环外；single 表示团队任选一人进入，不保证永远是编号 0 的人。第 171、178 行在已有团队内分派两个 for，没有再建立两个新团队；第 199–205 行派一人交换。第 162、166 行已经把事件耗时和转移计时起点分开，不能把这项改动记在 v7 名下。

## 1.7　v7　只把三行火带到手边

**这一版想干什么**：把第 r 行想象成书桌中间的纸：上面摊 r−1，下面摊 r+1。算完中间这行，就把中间移到上方、下面移到中间，再取一张新纸。这是火的临时视图，并不意味着整张旧森林已经被覆盖。

**卡在哪**：线程分界不能当森林边界。若一个线程从第 9 行起算，第 8 行也许属于隔壁线程，但它的旧火仍能点燃第 9 行。它可以直接读共享旧图，不必请邻线程把自己的私有窗口借出来。对方只写新图，因此不会在你读到一半时改掉第 8 行。

**这一版改了什么**：第 113–122 行按线程编号分行并准备三个私有容器。第 169–185 行在行段开始时装好窗口。第 191–200 行算四邻和两张新面，第 203–204 行轮换三个行容器，第 209–218 行等所有人写完，再由一人交换全图。题面编译命令没有显式启用 OpenMP；算法能分行，不等于评测程序真的会并行。
