# 附录 B　复杂度与性能账本

**这一章你会得到什么**：给定边长、步数和实际参加工作的核数，能算出容量、逻辑工作量和时间预算，也知道哪里必须停下来要实测数据。

## B.1　先讲记账单位

设 n 为边长，t 为步数，W=⌈n/64⌉，P 为单进程实际工作线程数；Z=(n+2)W 是作者位图中一张面的字数。下表统计主要状态空间，输入文本、事件记录、输出缓冲另记。时间复杂度（time complexity，规模增大时操作次数的增长方式）和空间复杂度（space complexity，活跃存储随规模增长的方式）不是秒数或内存监控截图。按字计的一轮 nW 与按格计的 n² 在固定位宽机器上的渐近阶仍相同，差的是每次操作干多少格。

|版|每步转移的工作与额外工作|主要状态空间，不含文本|实测与可推算的上限|
|---|---|---|---|
|v1|n² 个格判断，加两次大图复制量级；回春逐格|两个 (n+2)² 的 int 网格，行容器额外计|未附全程实测；无并行队伍，不能预算成 64 核|
|v2|同为 n² 判断，不再两遍整图复制；回春逐格|两张二维 int，预分配；新增整文件及 4 MiB 输出缓冲|未附；省复制不等于总时长减半|
|v3|n² 个字节状态判断；回春逐格|2(n+2)² 字节，另有整文件与输出缓冲|未附；相对 v2 状态有效字节按 4 字节 int 约为四分之一|
|v4|扫 Z 字造 fire，再用 nW 个字更新|5×8Z 字节＝两张旧面、两张新面、一张火图|未附；每字含至多 64 格，不能写成整题 64 倍|

全程应对每步求和。对 v1–v3，若第 s 步回春面积为 Hₛ×Cₛ，它还须访问 HₛCₛ 格。对 v4–v8，横跨字数 Jₛ=⌊ey/64⌋−⌊sy/64⌋+1，要处理 HₛJₛ 个字，点惊雷则为常量次访问。br 回春还要裁剪所涉及的块。全图例外还要计一轮读入、一轮输出，不能把一个时间步的工作直接当成整题时间。固定 P、S 不意味着它们在工程预算里可以忽略。

**一句话记住**：先写“几格、几字、几块”，再谈每秒做多少。

## B.2　一张纸算完内存

二进制容量单位：1 KiB=1024 字节，1 MiB=1024 KiB，1 GiB=1024 MiB。取 n=16384，则 W=256，Z=4,194,816 字。一张带上下填充的位面用 33,558,528 字节，即 32 MiB 加 4 KiB。四张面约 128 MiB，第五张再加约 32 MiB。若 P=16，三行窗口合计 3×8×256×16=98,304 字节，即 96 KiB。两者之差是容量数量级，不代表每步都从主存传了同样多；芯片缓存能复用一部分数据。

按 LF、一位数字与一个分隔符计，大图格子文本约 512 MiB，还没算头行和事件。v2–v7 一次读完整文件，不能只看 v7 的 128 MiB 状态面就把它当全进程峰值。br 每批缓冲约 (2n+4)×1024 字节，即约 32 MiB；若多个进程都分配、都读，这部分也会重复。br 传给 halo 的四个空向量在当前入口没有解包；不能把一个并未实例填满的通信边界空间算成这条路径已发生的消耗。

**一句话记住**：两位可以表示一格，不等于全程序每格只占两位。

## B.3　速度能推到哪一步

公式 T(P)≈T串行+T可分/P+T等待+T额外搬运 是分析模型，不是拟合结果。假设某个虚构工作流的串行部分占 10%，可平分部分占 90%，且没有等待，用 16 核的理想加速为 1/(0.1+0.9/16)=6.4。这个例子只解释为什么“16 核”不是“16 倍”；材料没有给任何版本的 10% 比例。若工作单元原本已是 64 格的一字，线程分摊的是若干个字，不是把既有的处理速率再无条件乘 64。

满分预算 68 秒与基本分预算 110 秒，按全部 64 核分别约为 8.11 和 13.11 核纳秒/逻辑格；按一个 16 核节点而不跨节点分别约为 2.03 和 3.28。项目没有提供同步的编译选项、线程绑定、输入指纹、多个重复样本与正确性记录，所以不能给九个实现排速度名次。br 第 520 行注明创建线程探针实测 1.36 秒；没有原始输入和探针运行日志，只能标“源码作者记录的局部实测”，更不能把它从未知的总耗时直接减去当新成绩。

若将来拿到记录，先比同一输入的最终森林，再把读、事件、转移、输出的计时边界逐项对齐。以同一机器同一输入的基准中位耗时 T₀ 除候选中位耗时 T₁ 才是可核对的加速比；用题目时限除自己的耗时仅代表离目标还有多远。

**一句话记住**：时限给预算，源码给操作数，真实秒数只能由有条件记录的实验给出。
