# 附录 D　哪些地方还不能照注释下结论

**这一章你会得到什么**：把可以由源码直接证实的差异、依赖合法输入的写法、必须上机器才能回答的问题分开。书中不改任何原文件。

## D.1　题面、脚本和任务说明的分歧

|证据|看见的事实|本书怎么处理|
|---|---|---|
|v7 L221–261；br L676–716|任务说明的 221 与 676 都早于文件末行。v7 还没写输出，br 还没完成工作队和收尾。|按真实 261、716 行讲。|
|compare.py L7–29|文本模式逐行 split，再比每个字段字符串，不是逐字节。zip 在第一份文件较长而第二份刚耗尽时，可能预先消费第一份多出的一行，后面的 readline 就漏掉这行。|按 n 行 n 项输出；验书时另用独立小例检查比对器，不把这处宽容当成格式要求。|
|intro.md L48、52、57；gencase.py L72–85|题面先写 m 个事件，后文使用未另定义的 k；生成器头行和实际写出的都是事件总数。|书中统一写 m，遵守升序且每步最多一个。|
|PROMPT §0、§11|结构表列十章 Markdown，自检又要十一个。|保留十个指定文件，加一份独立阅读导引 README.md；进度与自检另计。|
|br L630–637、706–714；v8 L79–90|只有 v8 的可选 MPI 路径显式排除非零 rank；br 没有相同分支。|不替两份不同作者的实现调和成一个故事。|
|br L174–186、533–549、663–704|当前池用自旋锁领取任务、自旋栅栏等阶段，没用条件变量。|分开说明旧 node_step 与 main 实际调用的 process_tasks。|

**一句话记住**：作者注释、任务摘要和可执行路径不一致时，先追路径。

## D.2　正确读懂合法输入之外的前提

|位置|证据与影响|
|---|---|
|v1 L79；v2 L98；v7 L131|晚到的条目可以在 <= 的版本被消费，但游标不会越过队首的未来条目；这些写法不是排序器。|
|v2 L28–34；v7 L32–38|v2 不检查短读，v7 检查短读，但没有检查 fseek/ftell 失败。返回负长度、极大文件或不能定位的文件不在其稳健范围内。|
|v7 L49–53、69–79、91–98|数字读取允许跳过非数字，到尾可能返回 0；逐格查表假设输入字符在 0..3。正常题面给出保证，任意外来文本没有同样保证。|
|v7 L60–61、116|使用 size_t 不会撤销先前的有符号计算；n+63、n+2 等仍先在 int 中计算。题目尺寸可以表示，不代表任意输入均安全。|
|v7 L230–244；v8 L305–316；br L561–575|写满后 q 等于 qend，计算 q+2 可能已越过可构造的一过尾指针；即使最终只用它作比较，也不是可移植的边界判断。用剩余空间的概念理解其意图。|
|v7 L235、253–254；br L565、584–585|fwrite 的返回项数与 fclose 结果未查，正常退出不能排除后期写盘失败。|
|v7 L111–114、212–228|没有 MPI 的 rank 筛选；被外部启动多个进程时，各份并不协调同一输出路径。|
|v8 L31–35、79–89、103–115、300–304、333–335|检测头文件不等于验证链接；非零 rank 进入集体收尾，不保证立刻退进程。0 号有错误分支未配对 Finalize。|
|v8 L54、176–186、240、279–297|注释中的时延倍数和“归还给系统”不是可复验的保证。硬件并发提示不是绑定核数，两个阶段计时也偏向 0 号视角。|
|br L289–320、330–340、622–640|注释说四个象限，local_side 却改成 n，起始行列仍乘 rank 坐标。固定 16384 和块宽 1024 与读取尺寸共同决定下标；不能声称通用小规模或 64 rank 可运行。|
|br L315–340、633–637、649–656|按第一行的字节跨度和每格两字节定位；多空格、不同换行宽度或文件读取失败不能按同样方式解释。fopen、fgets、sscanf 的关键返回量也没有完整核查。|
|br L446–515、658–661、684–708|边缘打包器和还原器存在，主路径没有调用；输出无唯一写者。不能从 MPI_Init 推断已做跨进程边界交换或聚合。|
|br L1、517–531；intro.md L243–250|源码依赖独立 spin_lock.hpp，题面只收一个 cpp；原文件组合不能当作可直接提交的单文件。|
|std-main.cpp L120–131、155|参考实现访问 events[cur_event_id] 前没有显式检查游标仍小于事件数。规则解释以题面及合法事件的行为为准，不推定参考程序对所有边缘输入都稳健。|

**一句话记住**：能在题目保证下解释一个程序，不等于已经证明它能处理所有文件与启动方式。

## D.3　待验证的性能与平台问题

没有比赛容器、完整编译日志、原始计时记录，无法确认 v7 在现场具体是忽略指令后串行运行，还是缺少运行库符号而链接失败。v8 的自旋在指定绑定下是否合算、br 的活动队列在这组火势里有多少块能跳过，也没有实测证据。源码中的探针注释与题面预算各自保留，不以推算填补成绩空格。

编译器行为可对照 [Intel 对 OpenMP 开关的说明](https://www.intel.com/content/www/us/en/docs/dpcpp-cpp-compiler/developer-guide-reference/2025-1/fopenmp.html)；同步语义见 [OpenMP 的 single 规范](https://www.openmp.org/spec-html/5.1/openmpsu43.html)；进程结束的集体性质见 [MPI Forum 的 Finalize 说明](https://www.mpi-forum.org/docs/mpi-2.0/mpi-20-html/node32.htm)。链接供深入查阅，阅读本书无需联网。

**一句话记住**：原题规定“怎么评”，源文件显示“写了什么”，这两者之间还差一份真实运行记录。
